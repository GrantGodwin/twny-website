outstanding, and what is deliberately deferred. Brand and visual decisions are governed by
[`governance/implementation-brief.md`](./governance/implementation-brief.md) and
[`governance/art-direction.md`](./governance/art-direction.md) — this document does not
restate or override either. The implementation brief remains the design and implementation
contract; this roadmap is the execution backlog.

## Phase 3 — Supporting Pages

**Launch consists of exactly three pages: Home, Services, Contact.** Nothing else is required for launch.

- [ ] Services — **the next milestone, and the last page required for launch.** A minimal placeholder exists at `/services` (`src/pages/services.astro`); it is not the designed page. **IA is locked, implementation is not:** organised around the same four business-capability themes already established on the homepage (Work smoothly / Look professional / Stay protected / Save time) — not by delivery model (recurring vs. project work) and not by a technology catalogue (Microsoft 365 / Security / Backup / Websites / AI as equal entries). Named technologies appear *inside* each relevant capability as supporting detail, recurring across more than one capability where genuinely relevant, rather than each owning one canonical section. A "Projects & advice" note may exist as a minor supporting section, not an organising category. No standalone FAQ page — FAQs are written fresh for this page's real scoping/fit questions and embedded only where they belong; the old pricing FAQs are not reused. No partners page, logo wall, or certification strip — a genuine partner credential, if one exists, is mentioned inline within the one capability it actually strengthens, never as a separate section. Absorbs any content from `/productivity` worth keeping (see below) and permanently retires the `/#services` anchor question. See the design brief under discussion for full detail.
- [ ] ~~Pricing~~ — **removed from the website entirely, by strategic decision.** Not a Phase 3 deliverable any more — there is no "build/review the pricing page" task. `/pricing.astro` is to be deleted as part of the Services implementation. Pricing figure sign-off (previously tracked in the Product Backlog) is moot and has been removed from this document.
- [ ] ~~Productivity~~ — **will not survive as a standalone destination.** `/productivity.astro` is, as built today, a second pricing page under a different name (`TierLadder`, `PricingToggle`, `PricingFlag`, `ComparisonMatrix`) — all of that is discarded with Pricing. Its non-pricing explanatory content (e.g. the "what 'managed' means" plain-English explainer) is a candidate for absorption into Services if it earns a place there during implementation; it is not preserved as its own page or destination either way.
- [ ] Contact — `/contact` exists as a placeholder only; no form backend, no guided recommendation flow. Required for launch as a page; the form backend is separate, longer-running work (see Product Backlog).
- [ ] Privacy — **not in the locked launch scope, and not yet assigned anywhere else.** No privacy page exists; legal content and scope are undefined. Flagging this as a gap rather than silently dropping it — confirm whether a launch with no privacy page is acceptable before treating this as fully deferred.

## Phase 4 — Launch

Implementation tasks only.

- [x] Metadata — per-page `<title>` and `<meta description>`; canonical URLs on every page, derived from one central base URL in `astro.config.mjs`.
- [x] **Canonical origin — `https://www.twny.com.au`, written down rather than inferred.** The base URL previously resolved through `VERCEL_PROJECT_PRODUCTION_URL`, on the assumption that the variable would follow the custom domain once one was attached. It did not: after the cutover, production kept building with `twny-website.vercel.app`, so every canonical, `og:url`, sitemap entry and robots `Sitemap:` line on the live site pointed at the deployment URL. The canonical host is a product decision, so it is now a constant (`PUBLIC_SITE_URL` still overrides). www is canonical because the apex redirects to it at the platform level. Guarded by `npm run verify`.
- [x] **Legacy URL cutover** — permanent (308) redirects in `vercel.json` for the WordPress routes catalogued in [`archive/research/discovery-external.md`](./archive/research/discovery-external.md): `/about-us/` → `/`, `/get-in-touch/` and `/contact-us/` → `/contact`, and the four `/services/*` pages (business-productivity-tools, business-website-hosting, managed-services-consulting, cloud-platforms) → `/services`. Both slash forms are listed explicitly rather than relying on platform normalisation. `/news/` is deliberately **not** redirected — a defunct article index has no honest equivalent here, so it gets the branded 404 instead.
- [x] **Branded 404** — `src/pages/404.astro`, built to `404.html` and served by Vercel with a real 404 status. Shared header/footer, existing visual system, three routes back. Not in the sitemap, not in navigation, `noindex`.
- [x] **Icons** — `public/favicon.svg` was still Astro's default rocket, and no icon `<link>` was emitted at all, so the browser was falling back to a stale `favicon.ico`. Replaced with the wordmark set in Space Grotesk on the Sand ground, rasterised to `favicon.ico` / `favicon-32.png` / `favicon-192.png` / `apple-touch-icon.png` and referenced from `BaseLayout`. **This is the wordmark, not a new device** — the identity is still wordmark-only (see `Wordmark.astro`). If a purpose-drawn mark is ever commissioned, swap these four files.
- [x] Open Graph — full og:* set plus Twitter `summary_large_image`, with a 1200×630 card cropped from the approved hero asset. **A purpose-designed OG card carrying the wordmark would be better than a photo crop; commission when convenient.** Deferred again in the closeout pass rather than hold up the deployment.
- [x] Sitemap — hand-built endpoint listing exactly Home, Services and Contact. Add an entry only when a real page is added.
- [x] robots.txt — endpoint keyed on `VERCEL_ENV`. Default-allow by design: only an explicit `preview` build disallows crawling, so a missing variable can never block production.
- [x] Structured data — Organization site-wide; Service ×2 and FAQPage on `/services`, generated from the same source the page renders so markup cannot drift from visible content. No address, phone, hours, ratings or reviews: none are established. `ProfessionalService` was deliberately **not** used — it is a `LocalBusiness` subtype whose expected properties are address/geo/openingHours, which would invite exactly that fabrication.
- [x] Performance — fonts self-hosted (two third-party origins removed); hero served through Astro's image pipeline with a five-width srcset. Mobile home page now transfers ~151 KB total, with the hero at 8 KB instead of the 261 KB master.
- [x] Security headers — `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`, `Cross-Origin-Opener-Policy`, `Permissions-Policy`, plus immutable caching for `/_astro/*`, via `vercel.json`.
- [ ] **Content-Security-Policy — deferred, not forgotten.** A working policy is `default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self'; object-src 'none'; base-uri 'self'; frame-ancestors 'none'; form-action 'self'`. It is not shipped because it would block the Vercel preview toolbar (`vercel.live`), and because `form-action 'self'` and `script-src` would need widening the moment a third-party form handler or analytics is added. Ship it once the contact and analytics decisions below are settled, adding the origins those choices require.
- [ ] **Analytics — deferred, needs Grant.** Nothing is installed and no IDs were invented. To enable Vercel Analytics: turn it on in the Vercel dashboard (Project → Analytics), then `npm i @vercel/analytics` and mount its component in `BaseLayout.astro`. Adding analytics makes the Privacy page below mandatory.
- [ ] **Contact form backend — deferred, needs a decision.** The site is a static build with no server runtime and no mail-sending credentials, so a form cannot be added without either (a) an Astro server adapter plus a mail provider API key, or (b) a hosted form endpoint. Email remains the working path and is now centralised in `src/data/site.ts` with a prefilled subject.
- [ ] **Privacy page — deferred, conditional.** Not added: the site currently sets no cookies, runs no analytics and collects nothing — a page would describe an empty set. It becomes **mandatory** the moment the contact form or analytics lands, and the footer needs its link at the same time.
- [x] **Motion** — the hero heading previously sat at zero opacity for 500 ms and settled at ~1.2 s. Now: heading starts revealing at ~124 ms and is settled at ~450 ms. Scroll reveals shortened from 700 ms to 450 ms and the observer pre-triggers 12% of a viewport below the fold, so a fast scroll no longer lands on a section that is still blank. Reduced motion still shows everything immediately.
- [x] **Wordmark assembly** — separate from the page motion above, and corrected twice. It first ran to 3 s (the brand name still assembling long after the hero had settled), was then over-corrected to ~0.9 s (too fast to read as a sequence at all), and now runs at a deliberate 460 ms stagger per letter: first letter at 200 ms, last letter starting at 1.58 s and resolving 1.15 s later — the sequence completes at ~2.73 s and is optically settled at ~2.44 s. Soft fade, a 0.1em rise and a blur→sharp resolve; no scale, bounce, overshoot or elastic easing. Nothing else waits for it and the link is clickable throughout. Timing is asserted from the built CSS by `npm run verify`, because it has drifted twice.
- [x] **Homepage narrative order** — hero → what we help with → how we work → why TWNY → both halves in practice → closing CTA. The engagement model used to sit above the areas of help, and the hero's scroll cue skipped a section. Both are now asserted by `npm run verify` (section order and the cue's destination).
- [x] **Capability cards rebuilt from the service model** — the four homepage columns were benefit-led abstractions (Work smoothly / Look professional / Stay protected / Work smarter) that traced back to nothing. They are now Day-to-day technology, Security and continuity, Websites and digital presence, and Specialist projects and advice: plain-English areas of help, each aggregating work that genuinely appears on the Services page under Managed Technology, Professional Services or both. The two public service propositions are unchanged and there are still only two.
- [x] **Capability icons** — one family, Phosphor Regular (`devices`, `shield-check`, `browser`, `tree-structure`), vendored as four local SVGs under `src/assets/icons/phosphor/` with the MIT licence and a provenance README. Compiled inline by Astro's SVG import, so there is no icon font, no runtime library and no extra request; **no package was added for four glyphs**, and `npm run verify` asserts that.
- [x] **Client work split by engagement type** — one region per engagement type rather than an undifferentiated grid: Concrete Sales carries Managed Technology as a single larger example; Stiles Advisory, Baza Capital and Deller Constructions carry Professional Services. Counts are deliberately unequal. Service pills are outline-only, consistent, and wrap cleanly at 360 px. **Still factual interim proof** — no quotation marks, attributed praise, logos, metrics, storage quantities or outcome claims, and nothing implying client review or approval.
- [x] **Retired client-stories scaffold deleted** — `stories` in `src/data/offer.ts`, `ClientStories.astro` and `ServiceIcon.astro` were unrendered dead code carrying invented person names and invented quotes. Removed rather than left in the tree; `npm run verify` already blocks every one of those strings from reaching the output.
- [x] **Footer rebuilt as a brand bookend** — wordmark, "Technology, simplified.", the positioning line, Services, Contact, `hello@twny.com.au` and the copyright. The support-hours statement ("business hours, with best-effort out of hours") is **removed from the public site**: it belongs in a service agreement, proposal or support arrangement where it can be stated accurately for a specific client. `npm run verify` blocks its return.
- [x] **Ownership language corrected site-wide** — TWNY owns the *problem* and stays accountable; the client owns its domains, data, systems and decisions. "Take ownership of", "own your technology", "we take on your environment" and the contrived "five providers" are gone, and asserted absent. The locked principle "We own the problem." is unchanged, and so is the Services passage stating that domains stay registered in the client's name.
- [x] **Build-output verification** — `npm run verify` (build, then `scripts/check-build.mjs`). 157 assertions covering the canonical host and per-page canonical path, `og:`/`twitter:` URLs, title/description presence and uniqueness, one `<h1>` per page, absence of any `vercel.app`/`localhost` string in the output, sitemap and robots contents, no public pricing in rendered text, no retired scaffold proof or legacy positioning, a single consistent `mailto:`, icon presence and references, internal links resolving to built pages, and the 404's status markers. The editorial pass added: homepage section order and the hero cue's destination, every line of locked copy, both engagement types and the three levels, the retired ownership and support-hours phrasing, the retired benefit-led headings, fabricated-proof patterns (curly quotes, percentages, storage quantities, savings, endorsement language), the footer's contents, the wordmark's stagger and settle time read from the built CSS, and the vendored icon licence. Each new guard was negative-tested. Also `npm run check` (`astro check`): 0 errors, 0 warnings.
- [ ] Google Search Console — **needs Grant's account.** Submit `https://www.twny.com.au/sitemap.xml`. Not done in this pass: no Search Console access from the build environment.
- [ ] Accessibility review — skip link, `:focus-visible`, `aria-current`, mobile-menu ARIA, accessible names on every control, decorative-image `alt`, and reduced-motion behaviour all verified by browser QA each pass, and text contrast is now measured from the rendered pages at four viewports (no pair below its WCAG AA floor). Still **no formal third-party audit**.
- [ ] **Dependency advisories — noted, not actioned in this pass.** `npm audit` reports 7 findings (postcss path traversal; sharp/libvips CVEs; svgo `removeScripts`), all in build-time tooling that never reaches the browser on a static build. Deliberately not remediated inside a domain-cutover PR, where a transitive bump risks the deployment. Worth a dedicated `npm audit fix` pass with its own build verification.
